## Действия и работающие адреса

- Создан минимальный локальный API-адаптер над существующими `MatchIngestionService` и `MatchAnalysisService`; алгоритмы Draft, Ruiner и Timeline не менялись. Маршруты существуют только при явном `DOTA_LOCAL_ALPHA=true` и отвергают не-loopback-клиентов, чужой Origin и нелокальную БД.
- В текущей локальной копии создан игнорируемый Git файл `frontend/.env.local` с `VITE_LOCAL_ALPHA=true`. Флаг backend **не** записан в `backend/.env`; его указывают только при запуске. Vite включает локальную ветку только в режиме `development`.
- Существующий визуальный стиль использован для компактного отображения API-данных. Отсутствующие оценки выводятся как «нет данных». Исправлено перенос строк навигации на узкой ширине и отложена загрузка Telegram SDK до реального входа через Telegram.
- FastAPI работает на **http://127.0.0.1:8000**; React/Vite — на **http://127.0.0.1:5173**. Proxy `/api` подтвердил связь между ними. OpenAPI: **http://127.0.0.1:8000/docs**.

## Реальный матч 9051271323

Путь браузерная форма → Vite proxy → FastAPI → OpenDota/PostgreSQL → разделы отчёта прошёл. Прямой запрос анализа занял 1,8 с; последующие запросы используют сохранённый отчёт. Итог текущего live-ответа: 32:13, счёт 10:45. В отчёте 10 игроков; Draft `FINAL_ONLY`, оценка Radiant 65.1/100, Dire `null`, все 10 оценок «на момент выбора» `null`; Ruiner `partial`, 10 игроков, уверенный кандидат не выбран; Timeline `complete`, 392 события, по 33 точки золота и опыта. Эти значения получены от текущего API и могут отличаться от старых тестовых снимков.

## Известные ограничения и следующий шаг Alpha

1. Telegram-проверка **BLOCKED**: в локальной конфигурации нет `BOT_TOKEN`, тестового отрицательного chat ID и подтверждённого Mini App HTTPS URL. `/match` зарегистрирован и покрыт существующими тестами, но реальное сообщение/кнопка бота не проверены. Для проверки нужно указать секреты локально и запустить `../.venv/bin/python -m app.bot.main` из `backend/` в третьем терминале, предварительно выбрав тестовую группу. В рабочие группы сообщений не отправлялось.
2. Графики золота/опыта, развернутая визуализация доказательств, фильтры событий и полноценный подробный UI ещё не реализованы. Сейчас показаны фактические значения, события и ограничения в компактных карточках существующего стиля.
3. Для экстремально большого, но формально допустимого bigint ID OpenDota ответил HTTP 500. Это ограничение внешнего источника; интерфейс правильно показывает временную недоступность. Перед полноценной Alpha стоит проверить сообщения об ошибках источника на нескольких реальных сценариях.
4. Локальный запрос анализа синхронный и при ошибке источника отвечает HTTP 200 с сообщением, после чего read-only отчёт отдаёт соответствующую ошибку. Перед полноценной Alpha стоит согласовать более явный контракт запуска/статуса.
5. Используется ручной локальный запуск в двух терминалах; нет проверки публичного HTTPS и реального Telegram WebApp в этом этапе.
