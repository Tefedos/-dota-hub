# Dota Hub — Backend вкладки «Игроки»

**Статус: READY FOR QA**, 23 октября 2026. Это техническая готовность к приёмке, не статус DONE. Проверены два независимых реальных матча: `8888765469` (не распарсен, `version=null`) и `9051271323` (распарсен, `version=22`), а также негативные фикстуры. Полный фактический ответ для первого матча: [players_8888765469_response.json](qa/players_8888765469_response.json). Match ID в рабочем коде не используется как условие.

## A. Аудит текущей реализации

Пайплайн сохранён: `backend/app/integrations/opendota.py` → `backend/app/services/match_normalization.py` → `backend/app/services/match_analysis.py` → REST DTO `backend/app/models/match_api.py`. До этой доработки в репозитории уже были корректные имена героев из `backend/app/data/hero_catalog.json`, публичные никнеймы из `personaname`, нейтральная подпись при их отсутствии, `obs_placed`/`sen_placed` и осторожная оценка линии через `lane_role`. Frontend уже показывал портреты из отдельного снимка того же закреплённого источника; в его код не вносились изменения.

Старый сохранённый отчёт `8888765469` ещё содержал `hero_name=null` и технические имена, хотя код был уже исправлен. После повторного анализа из текущего OpenDota он содержит 10 настоящих имён героев и 10 публичных никнеймов. Доступность никнейма конкретного игрока зависит от ответа источника; старые отчёты не следует использовать как доказательство отсутствия никнейма в OpenDota. `name`, `account_id` и прочие профильные поля намеренно отсекаются при сохранении; дополнительных запросов профиля нет.

У обоих матчей 10 участников и все базовые числовые поля. В сохранённом сыром ответе `9051271323` есть `stuns`, `level`, `buyback_count`, `backpack_0..2`, `lane_role`, `position_est`; у `8888765469` есть `level` и рюкзак, но нет `stuns`, `buyback_count`, `lane_role`, `position_est`. Код ранее не выводил часть этих полей. Старые числовые `items` и `neutral_item` были доступны без отображаемых сведений.

`status=ready` означает, что отчёт раздела сохранён. `completeness=full` для `players` означает **10 участников и полный набор `CORE_PLAYER_FIELDS`**, а не наличие никнейма, позиции, предметов и всех данных парсинга. `error` описывает ошибку получения/анализа и не подменяет ограничения отдельного поля. `position.confidence=1.0` относится к подтверждённому входному `lane_role` и означает доверие к указанной линии, не доказательство позиции фарма 1–5. Глобальная семантика конверта и `schema_version=1` не изменены.

## B. Изменения Backend

Добавлены **только опциональные поля** в `PublicPlayer`; прежние `player_slot`, `team`, `hero_id`, `items`, `neutral_item`, KDA, GPM/XPM и остальные поля не удалены и не переименованы. `model_version=players_v1` и глобальный `schema_version=1` сохранены, внутренний `config_version` изменён для пересчёта старых отчётов.

| Новое поле | Источник и смысл |
|---|---|
| `name_source`, `is_anonymous` | Наличие валидного публичного `personaname`; иначе `null`, `true` и «Анонимный игрок». Для старого отчёта без поля `is_anonymous` может быть `null`, чтобы не приписывать ему ложный статус. |
| `hero_image_url` | Существующий закреплённый каталог 127 героев; неизвестный ID → `null`. |
| `item_details`, `neutral_item_details` | Старые числовые `item_0..5`/`item_neutral` плюс закреплённый каталог предметов. Каждый известный предмет содержит `item_id`, `name`, `image_key`, `image_url`, `status`. ID `0` → `status=empty`; неизвестный ID → `status=unmapped`; отсутствующее значение → `null`. |
| `backpack_items`, `backpack_item_details` | `backpack_0..2` и тот же каталог; порядок слотов сохранён. |
| `level` | Целое `level` из матча, значение 1–100; неверное/отсутствующее → `null`. |
| `stun_duration_seconds` | Неотрицательное конечное число `stuns`; единица — секунда. |
| `buyback_count` | Неотрицательное целое `buyback_count`. |
| `performance_position` | `position_est` 1–5, только с `evidence=estimated` и `source_field=position_est`; отсутствие → `unknown`. `position` по `lane_role` не меняется. |
| `completeness_scope` | В `PlayersReport` явно указано `core_player_stats`. |
| `hero_catalog_revision`, `item_catalog_revision`, `limitations` | Версия справочников и конкретные ограничения доступности необязательных данных. Общий `MatchEnvelope.limitations` получает эти ограничения без изменения `completeness`. |

Справочники закреплены на ревизии [odota/dotaconstants `5c0242d`](https://github.com/odota/dotaconstants/tree/5c0242df9057848fa2036ca3fafe9f2bd4508163/build). В `hero_catalog.json` добавлены ссылки на изображения без изменения используемого Draft Analyzer набора полей. Новый `item_catalog.json` содержит 596 ID: 491 с проверенным отображаемым названием, 501 с URL изображения; отсутствие описания у остальных не маскируется выдуманным именем. Обновление делается через `scripts/update_player_catalogs.py`: после проверки новой ревизии меняется константа `REVISION`, затем скрипт заново формирует оба каталога, а тесты проверяют покрытие. Привязка к историческому патчу **не подтверждена** (`patch_scope=snapshot_unverified`); это снимок справочника, а не история инвентаря матча.

Изменённые файлы: `backend/app/models/matches.py`, `backend/app/models/match_api.py`, `backend/app/services/match_normalization.py`, `backend/app/services/match_analysis.py`, `backend/app/services/draft/config.py`, `backend/app/data/hero_catalog.json`, `backend/tests/test_match_normalization.py`, `backend/tests/test_group_flow.py`, `backend/tests/test_match_ingestion.py`, `backend/tests/fixtures/group_flow/contracts.json`. Созданы: `backend/app/services/player_catalog.py`, `backend/app/data/item_catalog.json`, `backend/tests/test_player_catalog.py`, `scripts/update_player_catalogs.py`, этот отчёт и `docs/qa/players_8888765469_response.json`. ## D. Незакрытые вопросы

- `damage_taken` требует отдельной проверенной модели агрегации по словарю источников. Покупки/`item_uses` не эквивалентны применению smoke или dust.
- Публичный kill participation не добавлен: на `8888765469` сумма убийств Radiant (28) не совпадает с командным счётом (30). Нужны правила качества знаменателя и отрицательные фикстуры, прежде чем показывать процент.
- `position_est` остаётся оценкой; подтверждённых позиций фарма 1–5 для обоих режимов данных нет. `lane_role` описывает линию и не превращается в роль.
- Историческое название/изображение предмета для патча матча не гарантировано текущим снимком каталога. При обновлении каталога нужна отдельная проверка патчей и доступности CDN. Старые ID без проверенного `dname` получают `unmapped`, не выдуманное название.
- Полный mypy ограничен старой аннотацией теста драфта; исправление этой аннотации можно выполнить отдельно без изменения алгоритма.
- Предложение для мастер-плана v0.1: PL-01/02 и backend-часть PL-05/07 пометить **READY FOR QA**, добавить подпункты на историзацию предметов, проверку kill participation и подтверждённые позиции; **DONE не устанавливать** до пользовательской приёмки и QA в Telegram.
