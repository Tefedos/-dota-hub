Исходного Git-коммита у проекта пока нет, поэтому перечень файлов ниже основан на проверке рабочего дерева, а не на сравнении с коммитом. Исторические результаты версии `draft-heuristic-v1` сохранены в [отчёте 07A](STAGE2_07A_REPORT.md); они не являются результатом текущей версии.

**Вывод для локальной Alpha:** исправленные контракты и обработка неполных данных готовы к дальнейшей интеграции. **Численная оценка реального матча №9051271323 не готова:** недостаточно подтверждённого для патча 60 механического материала и полных статистических пар. Интерфейс и API возвращают `null`, а не прежние необоснованные баллы. Это сознательное ограничение достоверности. Живая Telegram-группа и устройства в этом этапе не проверялись.

Доменное правило про AoE и иллюзии остаётся расширяемым правилом признаков. В логике нет ветки по Match ID или специального набора десяти героев. Реальный матч присутствует только в регрессионном снимке.

## Формула и источники

Веса осей не менялись: `matchup=0.30`, `synergy=0.25`, `balance=0.20`, `phase=0.15`, `win_condition=0.10`. Итог при минимум двух доступных осях и сумме их исходных весов не менее `0.55` равен `sum(weight × axis) / sum(available weight)`. Если порог не выполнен, итог `null`. Полный coverage означает 1.0; неполный численный расчёт получает `partial_evidence`, `evidence_coverage` и максимум низкую/среднюю уверенность. Личные оценки больше не используют командные оси. Конфигурационная гипотеза `composition_absent=25` оставлена для совместимости конфигурации, но в расчёте не используется.

Статистика: [публичный endpoint OpenDota `/heroes/{hero_id}/matchups`](https://api.opendota.com/api) возвращает общие `games_played`/`wins` без доказанной фильтрации по патчу. Для каждой пары при `games_played >= 100` используется `100 × (wins + 100) / (games_played + 200)`, то есть prior 200 игр с 50% исходной долей. При меньшей выборке сигнал пары отсутствует. Ось `matchup` требует сигнал для **каждого** известного соперника; недостающие пары не становятся 50. Статистическая причина имеет `aggregate_unknown` и low confidence, не становится доказательством контрпика. `404`, `429`, timeout, иные HTTP/сетевые ошибки и пустые/некорректные ответы покрыты тестами провайдера; его кэш хранит успешные ответы 3600 с, ошибки 60 с, при `429` действует общий cooldown. Для сохранённого отчёта применяется кэш анализа до изменения исходного матча или версии конфигурации.

Качественные профили 11 героев опираются на текущие страницы [Valve](https://www.dota2.com/heroes) и [OpenDota abilities `master`](https://raw.githubusercontent.com/odota/dotaconstants/master/build/abilities.json); эти источники сами по себе не подтверждают историю patch ID 60. Описательный каталог 127 героев зафиксирован по [конкретному коммиту OpenDota](https://raw.githubusercontent.com/odota/dotaconstants/5c0242df9057848fa2036ca3fafe9f2bd4508163/build/heroes.json), но не даёт механических чисел. Проверенная production-политика последовательности остаётся `game_mode=22`, `patch=46`, [Valve 7.27](https://www.dota2.com/patches/7.27); численно подтверждённых профилей для неё нет. Режимы/патчи без подтверждённой политики, включая проверенный матч patch=60, работают как `FINAL_ONLY`.

## Результат на матче 9051271323

Повторён сохранённый обезличенный снимок, затем 23 октября выполнен **отдельный живой запрос** к публичному OpenDota во временный каталог `/tmp/dota-hub-7a1-live`. Во втором запуске получены десять `ok` batches, но только **4 из 50** противоположных пар достигли порога 100 игр: по герою — Earthshaker 0/5, Sniper 0/5, Mirana 1/5, Kunkka 0/5, Undying 1/5, Hoodwink 2/5, Oracle 0/5, Death Prophet 0/5, Spectre 0/5, Chaos Knight 0/5. Полной оси `matchup` нет ни у одного героя. В обеих версиях evidence `mode=FINAL_ONLY`, `source_quality=[picks_roster_mismatch, visibility_policy_not_verified]`: исходная история содержит лишний pick Pudge, не входящий в финальный roster. Оценки `at_pick` и стадии не восстанавливаются.

Сокращение численных результатов — ожидаемое следствие проверки источников, а не ухудшение полноты входного ответа. `draft_advantage=insufficient_data`. Числа сравнивают разные моменты сбора внешней статистики; фиксированная `evidence.json` остаётся источником воспроизводимой регрессии. Живой smoke подтверждает доступность endpoint на момент проверки, но не постоянную доступность OpenDota.

Дальнейший Alpha-риск — неполное и неоднородное покрытие: 127 описательных записей, 11 качественных механических профилей на patch ID 60, **ноль production-профилей и правил с доказанной численной исторической применимостью**. OpenDota отдаёт агрегаты без гарантии патча, роли и периода; 429/сеть могут оставить часть batches пустой. Сохранённый отчёт воспроизводим по своему снимку, но исходные сырые matchup batches не лежат в отдельной постоянной таблице. Чтобы получать обоснованные численные оценки современных матчей, нужен версионированный исторический источник способностей и/или более полные статистические данные с понятным patch scope. Принудительно повышать coverage на текущих данных нельзя.
