# Dota Hub — Frontend вкладки «Обзор»

**Рекомендуемый статус: READY FOR QA.** OV-01–OV-06 реализованы на существующей странице матча. Коммит не создан. Backend и другие аналитические вкладки не менялись.

## Аудит и реализация

До доработки `MatchReportPage` получала Match ID из маршрута `/matches/:matchId` и загружала раздел через общий `getMatchSection`; локальная Alpha использовала `GET /api/v1/local-alpha/matches/{match_id}/overview`, Telegram-сценарий — авторизованный `GET /api/v1/matches/{match_id}/overview`. Существующий Overview в `SectionContent` выводил только счёт и технические ID. Верхние кнопки уже переключали разделы без отдельного маршрута для каждой вкладки. Карточки, цвета, отступы и адаптивная сетка находились в общей CSS-системе. Компонент портрета героя с fallback уже был во вкладке «Игроки».

Добавлен отдельный `OverviewSection` внутри прежней системы вкладок. Он показывает заголовок и понятный статус, счёт с выделением победителя по `winner`, четыре метаданные карточки, составы в порядке `player_slot`, три командных показателя и раскрывающиеся ограничения. Из `PlayersSection` повторно используется `HeroPortrait`; новые URL берутся исключительно из ответа Overview и допускаются только с закреплённого HTTPS CDN героев. Никнеймы отображаются как текст, длинные имена переносятся и доступны полностью через `title`.

Типы Overview отражают `overview_v2`; отсутствующие значения отображаются как `—`, «Не определён», «Нет данных» или «Анонимный игрок». Неподтверждённые башни и Roshan не превращаются в нули. Дата форматируется как UTC с явной подписью. Одинаковые вложенные и верхнеуровневые ограничения объединяются. `available_sections` не выдаётся за полноту хронологии; в качестве признака используются `data_quality`, `source_status` и `completeness`.

Загрузка сохраняет прежний API-клиент, авторизацию Telegram и локальный Alpha-маршрут. Запрос привязан к текущему Match ID и активному разделу; предыдущий ответ не показывается после переключения, запоздавший запрос отменяется. Сетевая ошибка преобразуется в понятное сообщение; существующая кнопка «Обновить» служит повторной попыткой. При пустом, но успешном ответе показано «Нет данных о матче». При частичном ответе сохраняются доступные поля и реальные участники без заполнения до десяти.

## Проверка реального API

В Chrome через локальный frontend и backend проверены:

| Match ID | Счёт | Игроков | Патч | Переполнение |
|---|---:|---:|---|---|
| `9057722463` | 44 : 42 | 10 | 7.41 | Нет |
| `8888765469` | 30 : 49 | 10 | 7.41 | Нет |
| `9051271323` | 10 : 45 | 10 | 7.41 | Нет |

Четвёртый, независимый состав `1000000001` проверен компонентным тестом на основе существующей fixture `backend/tests/fixtures/draft/independent.json`; это не живой ответ OpenDota. Незагруженный `9999999999` проверен в браузере на реальном локальном API: показано «Матч ещё не загружен. Запустите анализ ниже». 404 `NOT_FOUND` от OpenDota проверен подменённым API-ответом и тестом клиента. Специальных правил для этих ID в production-коде нет.
