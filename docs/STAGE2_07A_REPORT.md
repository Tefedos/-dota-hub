## B. Запуск и миграции

Все команды ниже выполняются из корня `dota-hub/`, если явно не указан переход в каталог.

Воспроизведение реально проверенного матча **без сети**, с перезаписью только сгенерированного `report.json`:

```sh
.venv/bin/python scripts/audit_draft.py 9051271323 \
  --output-dir backend/tests/fixtures/draft/9051271323 --offline
```

Новая live-проверка, с отдельным каталогом, чтобы сохранить регрессионную фикстуру:

```sh
.venv/bin/python scripts/audit_draft.py 9051271323 \
  --output-dir /tmp/dota-hub-draft-live
```

Команда обращается к публичному OpenDota без ключа, не пишет в БД, не отправляет сообщения и не запрашивает запуск парсинга replay. Запрашивается матч и не более десяти наборов матчапов; при 429 сбор прекращается. Промежуток между героями — одна секунда; transient retry ограничен одним повтором. Реальные данные могут меняться между запусками.

Вызов из приложения:

```python
from app.services.draft.analyzer import analyze_draft
from app.services.match_normalization import normalize_match_snapshot

normalized = normalize_match_snapshot(saved_snapshot)
report = analyze_draft(normalized, matchups=saved_matchup_batches)
payload = report.model_dump(mode="json")
```

Если статистики нет, `matchups` можно не передавать. Явный I/O-вариант — `await analyze_with_matchups(normalized, provider)`. Подключение в bot/FastAPI пока не выполнено автоматически.

Обычный локальный запуск сохраняется:

```sh
.venv/bin/python scripts/local_postgres.py start
cd backend
../.venv/bin/python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

В отдельном терминале, из корня:

```sh
cd frontend
npm run dev
```

Новых миграций нет. Для уже настроенной БД достаточно проверки:

```sh
cd backend
../.venv/bin/python -m alembic current
../.venv/bin/python -m alembic check
```

### Матч 9051271323

Источник: [OpenDota match API](https://api.opendota.com/api/matches/9051271323). Снимок и матчапы зафиксированы 22 октября 2026, итоговое время записи 17:12:42 UTC; у статистических строк есть собственные `fetched_at`.

- `game_mode=22`, `patch=60`.
- Radiant: Hoodwink, Oracle, Death Prophet, Spectre, Chaos Knight.
- Dire: Earthshaker, Sniper, Mirana, Kunkka, Undying.
- В `picks_bans` сохранено 16 действий: 11 pick и 5 ban. Pick Pudge (hero_id=14) не соответствует финальной десятке; дополнительные баны расположены после пиков. Ничего не удалено ради «исправления» порядка.
- Результат: `FINAL_ONLY`, причины `picks_roster_mismatch` и `visibility_policy_not_verified`; десять финальных героев, все `at_pick_score`, stage и порядковые номера событий оценки отсутствуют. Исходные action orders остаются в `actions` как данные источника.
- Механические профили покрывают 6/10 героев, описательный каталог — 10/10. Все пять Radiant покрыты; у Dire — только Earthshaker.
- Из 50 направленных вражеских пар только 4 имеют хотя бы 100 игр: Hoodwink↔Mirana и Hoodwink↔Undying. Остальные выборки отвергнуты как малые. Не заполнена целиком ни одна ось matchup по пяти соперникам; отдельные статистические аргументы сохранены.
- Team score Radiant = **65.1**, Dire = **null**, `draft_advantage=insufficient_data`. 65.1 — эвристическая полезность по доступным осям, не вероятность победы и не свидетельство превосходства над Dire.
- Финальные оценки: Hoodwink 64.3, Oracle 65.5, Death Prophet 65.2, Chaos Knight 65.2; Spectre и все герои Dire — null. У Spectre доступно 0.45 исходного веса, что ниже порога 0.55. У Dire неполное покрытие союзного контекста не позволяет итоговый score даже для Earthshaker.
- Отдельный тест меняет реальный исход, счёт и KDA при тех же драфте и статистике: отчёт остаётся идентичным.

Числа выше фиксируют выполненную проверку; они не зашиты в алгоритм или assertions тестов. При изменении версии модели или snapshot матчапов числа могут измениться.

## D. Негативные сценарии и отсутствие хардкода

PASS: отсутствующий/частичный picks_bans; дубли и gaps order; переставленный массив с корректными order; несовпадение команды/героя с roster; противоречивый team_code; конфликт ban/pick; несогласованные раунды; огромный order; неизвестные patch/hero IDs; неполный roster; отсутствующие позиции; маленькие/некорректные выборки; 404/429/5xx/timeout/invalid JSON; неизвестные IDs вне диапазона HTTP-клиента.

PASS: поздний Earthshaker влияет на final_context CK, но не на ранее рассчитанный at_pick. Герой внутри того же скрытого раунда не считается известным противнику и не называется поздним контрпиком.

PASS: **независимый состав** — Axe, Bane, Drow Ranger, Juggernaut, Mirana, Sven, Zeus, Lion, Leshrac, Lifestealer. Нет пересечения с 11 механическими профилями defaults. С production-конфигурацией доступны описательные признаки/статистика и честные null-оценки. Отдельные явно синтетические profiles и visibility policy проверяют численный движок на этом составе; их условные tags не выдаются за подтверждённые механики настоящих героев.

PASS: смена Match ID меняет только идентификатор отчёта; перенумерация всех героев вместе с конфигурацией сохраняет оценки; изменение состава без изменения исхода меняет оценки; изменение utility правила меняет оценки; добавление/удаление описательного каталога не меняет оценки. Частичная история независимого состава оставляет финальные оценки неизменными и убирает at_pick.

Проверка кода: в ядре нет веток по конкретному Match ID или заранее заданной десятке. Имена и ID находятся в данных профилей/каталога. Взаимодействия — версионированные tag-based rules с источниками, применимостью и reason codes. Oracle/Spectre/CK/Earthshaker не являются готовым ответом для матча; их последовательность используется в тестах. Единственная фиксированная численность 5+5 отражает поддерживаемый формат стандартного матча.

Источники покрытия: [закреплённый каталог OpenDota](https://raw.githubusercontent.com/odota/dotaconstants/5c0242df9057848fa2036ca3fafe9f2bd4508163/build/heroes.json), [способности](https://raw.githubusercontent.com/odota/dotaconstants/master/build/abilities.json), [Valve 7.27](https://www.dota2.com/patches/7.27). Подтверждения текущей видимости на patch=60 в проверенных первичных источниках не получено; молчание последующих patch notes не принято за доказательство.

`score=null` возвращается, когда:

1. Собственный герой или союзный контекст не покрыт профилями для данного патча, либо patch неизвестен.
2. Roster не полон или противоречив.
3. Доступно менее двух осей или менее 0.55 исходного веса. Недостающие оси не заменяются 50.
4. Для at_pick не подтверждены история/видимость, либо в раннем контексте слишком мало данных.

Отдельная ось matchup остаётся null, если хотя бы для одной рассматриваемой пары нет допустимого статистического или механического сигнала. Неполные механические справочники не превращают неизвестные способности в отрицательные признаки. Полностью отсутствующая статистика сама по себе не запрещает итоговую эвристическую оценку, если других осей достаточно. Laning и farm_economy всегда null до подтверждения позиций; предупреждения о фарме условные.

Веса 30/25/20/15/10, utility правил, presence/absence 75/25 и grade thresholds — конфигурационные гипотезы, не обученная модель. Confidence численного результата не выше medium. Статистика может быть собрана после разбираемого матча: историческая оценка с данными, реально существовавшими в тот момент, не заявляется. По поздним пикам контрфактическая delta может менять состав доступных осей; это не доказательство причинного влияния.

HTTP-кэш и single-flight действуют в одном процессе; persistent-cache для матчапов отсутствует. Новый wheel проверяет включение кода и справочника, но не является отдельным deployment bundle с миграциями/окружением.

## G. Готовность к интеграции и GAP-list для 09 / этапа 3

Можно выполнять следующее отдельно заданное интеграционное задание: внутренний модуль имеет проверяемый вход/выход и безопасную деградацию. Интегратор обязан сохранять mode, model_version, source_refs, coverage и null, а не преобразовывать их в обвинения, 0 или 50. Готовность всего пользовательского сценария «бот опубликовал полноценный анализ современного драфта» не заявляется.

Оставшиеся пробелы:

1. Подтвердить современную режимную политику и согласовать её патчи с механическими профилями. Отдельно проверить Captains Mode.
2. Расширить проверенные механики героев, ревизии/subpatch/facets; провалидировать utility и пороги на независимых составах. 127 описательных записей не закрывают этот пробел.
3. Получать подтверждённые позиции, если продукту нужны линии и экономика. Не выводить их из результата игры или имени героя.
4. Согласовать сохранение отчёта и evidence snapshot, срок жизни статистики, обновление по model_version, доступ к матчу и HTTP API. Учесть общий бюджет OpenDota между вызывающими процессами.
5. Подключить внутренний анализ к bot pipeline с контролем ошибок и временем ответа, затем публикацию и Telegram smoke. Различать успешное получение матча и достаточность данных анализа.
6. На этапе 3 отображать FINAL_ONLY, неизвестные оценки и качество данных; не рисовать стадии при отсутствии достоверной истории.

Рекомендации альтернативных героев и другие функции v2 не реализовывались и не включены в текущую готовность.
