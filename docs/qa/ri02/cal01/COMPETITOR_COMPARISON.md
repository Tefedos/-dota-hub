# RI-02-CAL-01 — Who Ruined?

Проверены [публичный сайт](https://china8sd.github.io/who-ruined/) и [репозиторий автора](https://github.com/china8sd/who-ruined). README описывает публичную ссылку `?match=ID`, клиентский анализ OpenDota, оценку поражения, роль, поправку по рангу и исключение leaver из выбора. Это **описание самого сервиса**, не проверка корректности его вывода. В доступной среде удалось открыть только исходную пустую страницу; завершённые динамические отчёты по тем же Match ID и разрешённый публичный API результатов не обнаружены. CAPTCHA/авторизацию не обходили, анализ не запускали от имени пользователя, нулевые значения конкурента не выдумывали.

`competitor_manual_registry.json` содержит **12 прямых ссылок** вида `https://china8sd.github.io/who-ruined/?match=ID` для ручной проверки совпадающих матчей. `competitor_result=null` означает **нет наблюдения**, а не нулевую оценку. Числового сопоставления и проверки конкретных объяснений пока нет; статус этой части **BLOCKED: нужна ручная браузерная фиксация публичных результатов либо разрешённый машинный интерфейс**. Если отчёт доступен вручную, фиксировать player slot/hero, исходную шкалу, текст и наблюдаемые эпизоды отдельно; не приводить оценку конкурента к шкале Dota Hub без валидной калибровки.

Различие постановки задачи подтверждено только документацией и нашим кодом: Dota Hub рассчитывает относительные отрицательные отклонения **для обеих команд** без использования победителя; Who Ruined? позиционирует анализ **влияния на поражение** и показывает одного «руинера» проигравшей стороны. Сходство/противоречие по конкретным игрокам не подтверждено.
