# RI-02-CAL-01 — ориентиры OpenDota

Read-only проверка двух героев пилота: `GET /benchmarks?hero_id=67&role=core` и `GET /benchmarks?hero_id=111&role=support`, оба HTTP 200. Ответы и SHA-256 находятся в `benchmark_samples.json`; точные JSON лежат в локальной gitignored директории `raw/`. **В действующую формулу данные не подключались.**

| Метрика ответа | Spectre Core P50 | Oracle Support P50 | Сопоставление с текущим RI |
|---|---:|---:|---|
| gold_per_min | 614 | 318 | Core economy, но патч/рейтинг не сопоставлены |
| xp_per_min | 895 | 507 | Core economy, те же ограничения |
| kills_per_min | 0,2611 | 0,1017 | В RI отдельно не штрафуется |
| deaths_per_min | 0,1542 | 0,2141 | Есть survival, но направление и контекст требуют проверки |
| assists_per_min | 0,3852 | 0,5016 | Не эквивалентно `(K+A)/team_score` |
| last_hits_per_min | 7,2245 | 1,0047 | В RI не используется |
| denies_per_min | 0,1989 | 0,0456 | В RI не используется |
| hero_damage_per_min | 953,36 | 249,23 | Core impact; у Support лишь credit |
| hero_healing_per_min | 0 | 323,22 | В RI credit-only, отсутствие лечения не штрафуется |
| tower_damage | 3853 | 173 | **Итог за матч**, не DPM; в RI credit-only |

Каждая метрика вернула 11 пар `percentile/value`, от 0,1 до 0,99. P50 здесь — возвращённый порог распределения игроков соответствующего героя и укрупнённой роли, **не оценка конкретной ошибки** и не размер выборки. Ответ не содержит `sample_size`, даты начала/конца совокупности, patch, конкретной позиции 1–5 или неопределённости порога. Число 11 — число точек кривой, а не число матчей. Документировать точное определение percentiles без исходного кода расчёта нельзя; практическое чтение — эмпирические пороги метрик, не стандарты должного поведения.

[Слитое изменение OpenDota от 03.10.2026](https://github.com/odota/core/pull/2984) описывает роль `core/support`: **top 3 команды по GPM** считаются core, остальные support; точная позиция 1–5 из API ненадёжна. Role-only фильтр работает отдельно от bracket, но источники этих фильтров ограничены доступными матчами; при отсутствии полного состава роль не формируется, Turbo отдельно. Это не независимое доказательство реальной игровой роли. Bracket-фильтр доступен, но у пилотной Spectre нет подтверждённого индивидуального рейтинга, поэтому не запрашивался и не подставлялся. Для новых матчей `avg_rank_tier` — средний уровень матча, не уровень конкретного игрока.

OpenDota хранит benchmark-наборы по временным эпохам, согласно [PR об укрупнённых ролях](https://github.com/odota/core/pull/2984) и [конфигурации retention](https://github.com/odota/core/blob/master/config.ts). В проверенном API нет параметра `patch`; текущие percentiles нельзя переносить на исторические патчи без отдельной процедуры. Все 12 матчей нашего пилота имеют patch ID 60, но неизвестна точная временная совокупность возвращённых benchmarks. Возможны смещения из-за публичности матчей, отбора в базу, доступности рейтинга, различий длительности, героев и топ-3-GPM правила. Исходные `ruiner_v1` оси по данным сравнимых союзников и OpenDota population percentiles имеют разный смысл и не должны механически складываться.

Вывод для следующего исследования: при наличии даты/патча, размера выборки, bracket и подтверждённой роли можно изучать внешние ориентиры отдельно от `ruiner_v1`; сначала проверить стабильность и экспертную интерпретацию. Для Spectre GPM 358 против текущего P50 614 — наблюдаемое различие двух несопоставленных контекстов, **не доказательство ошибки**.
