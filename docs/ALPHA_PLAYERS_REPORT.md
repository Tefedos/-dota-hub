# Dota Hub — Local Alpha, вкладка «Игроки» (промпт №11)

Проверено 23 октября 2026 года на матче `9051271323`. Номер матча используется только для QA; рабочий код не содержит отдельных условий для него.

## Найденные проблемы и причины

| Проблема | Причина | Исправление |

| «Герой #123» и другие числовые подписи | В нормализацию матча не передавался уже загружаемый каталог имён героев. | Передача каталога в `normalize_match_snapshot`; в UI — резервное сопоставление через единый каталог из 127 героев. |

| Нет портретов, смешаны команды, крупные карточки | Раздел отображался общей сеткой с минимумом полей. | Портреты из закреплённого каталога OpenDota/Steam CDN, две команды по `team`, стабильный порядок по `player_slot`, компактные строки с дополнительными деталями. |
| Техническая надпись об успешном получении данных | Универсальный текст статуса показывался после успешной загрузки. | Текст убран; состояния загрузки, ошибки и отсутствия матча сохранены. |

## Данные и поведение

До изменений API уже возвращал `hero_id`, `player_slot`, `team`, KDA, GPM/XPM, net worth, урон героям и строениям, лечение, добивания, отказы и подтверждённую информацию о линии. Запросы OpenDota ради этих показателей не добавлялись. OpenDota предоставлял никнеймы всех 10 игроков данного матча, но прежняя обработка их удаляла. В публичном DTO дополнительно выведены уже нормализованные `obs_placed` и `sen_placed`.

Портреты и резервные имена для 127 героев получены из закреплённой версии [каталога OpenDota](https://raw.githubusercontent.com/odota/dotaconstants/5c0242df9057848fa2036ca3fafe9f2bd4508163/build/heroes.json); изображения загружаются с Steam CDN. При неизвестном `hero_id` или ошибке загрузки изображения интерфейс остаётся работоспособным и показывает нейтральную заглушку. Внешний CDN нужен для портретов, но не для числовой статистики.

Отсутствующее число отображается знаком `—`; подтверждённый ноль остаётся нулём. Детали раскрываются только при наличии значений. Линия показывается только при подтверждённом `lane_role`; позиция 1–5 не выводится, поскольку таких подтверждённых данных нет. Если один из основных показателей отсутствует или игроков меньше десяти, раздел сообщает о неполных данных.

После обновления локального анализа API вернул 10 игроков: 5 Radiant и 5 Dire, 10 настоящих имён героев и 10 доступных никнеймов. Для всех игроков числовые поля KDA, GPM/XPM, net worth, урона, лечения и добиваний остались равны ответу API до изменений. `account_id` и `steam_id` в публичных записях отсутствуют.

## Локальный запуск

Из корня `dota-hub/` при работающей PostgreSQL и настроенном `.env`:

```bash
cd backend
DOTA_LOCAL_ALPHA=true ../.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В другом окне:

```bash
cd frontend
VITE_LOCAL_ALPHA=true npm run dev -- --host 127.0.0.1 --port 5173
```

Открыть `http://127.0.0.1:5173/matches/9051271323`, перейти во вкладку «Игроки». Если сохранён старый анализ матча, нажать «Запросить анализ из OpenDota» один раз для обновления данных.

## Оставшиеся ограничения

- Никнейм зависит от публичных данных OpenDota и может отсутствовать у другого игрока; тогда показывается «Анонимный игрок».
- Портреты зависят от доступности внешнего Steam CDN; при ошибке появляется нейтральная заглушка.
- В закреплённом каталоге 127 героев. Добавленный в будущем герой до обновления каталога будет показан как неизвестный.
- Точная игровая позиция 1–5 не выводится без достоверного источника. Сохранённая линия показывается только при подтверждённом `lane_role`.
