## Данные, кэш и ошибки

Независимый живой запуск 23 октября 2026 в 08:27 UTC сохранил обезличенные evidence во временный каталог `/tmp/dota-hub-alpha-regression-live`: 10/10 batches `ok`, все 50 направленных пар представлены, **4 пары имеют ≥100 игр**, 46 — меньше; диапазон 4–188 игр, медиана 17. Текущий локальный API также содержит ровно четыре `aggregate_matchup_signal` с `games_played` и временными метками того же дня; `evidence_digest` не равен SHA-256 пустого списка. Следовательно, `matchup=null` не означает, что запросы пропали. [Официальная OpenAPI-схема OpenDota](https://api.opendota.com/api) для `/heroes/{hero_id}/matchups` описывает `hero_id`, `games_played`, `wins` и не объявляет фильтр по patch/позиции; агрегаты нельзя выдавать за статистику патча 60.

Повторный `POST /api/v1/local-alpha/matches/9051271323/analyze` вернул «Из сохранённого анализа.»: неизменный snapshot и версия конфигурации используют сохранённый отчёт, поэтому повтор не обращается к matchup endpoint. Провайдер отдельно кэширует успешные ответы на 3600 с, ошибки на 60 с; `429` останавливает серию и включает общий cooldown. Это проверено существующими unit-тестами. В **текущем** отчёте ошибок/`429` нет. Постоянный кэш отчёта может удерживать устаревшую агрегатную статистику до изменения snapshot/версии конфигурации — это риск свежести, но не причина данной регрессии. Отдельные сырые batches в БД не хранятся; для точного воспроизведения внешних строк нужна сохранённая evidence-фикстура.

## Что нужно для обоснованных оценок произвольных матчей

1. Исторический источник patch ID ↔ версия/дата игры и зафиксированные **на дату матча** способности, facet/таланты и изменения героев. Нужна явная проверка версии каждого профиля и каждого правила; ссылка на текущую страницу или `master` для этого недостаточна.
2. Расширение качественных профилей за пределы нынешних 11 героев с указанием источника и границ применимости. Для этого матча сейчас отсутствуют профили Sniper, Mirana, Kunkka и Undying; полный союзный контекст обязателен для численной оценки. Справочник 127 имён не заменяет профили механик.
3. Численная калибровка utility взаимодействий и командных функций на независимых данных, а не повторное включение гипотетических 65/75. Направление и каноническая идентичность правила должны оставаться явными. Для линий и экономики нужны обоснованные **до пика** признаки позиций; post-game `lane_role` не подходит.
4. Матчап-статистика с доказанными patch scope, периодом, режимом/брекетом и, если используется, ролью; достаточные игры по всем рассматриваемым парам либо новая заранее обоснованная политика частичного покрытия, проверенная на разных матчах. Нынешний `/heroes/{hero_id}/matchups` не даёт гарантии patch scope. Изменять порог 100 лишь ради результата матча 9051271323 нельзя.
5. Для `at_pick` отдельно нужна подтверждённая политика видимости на patch=60 и согласованная история пиков. Лишний pick Pudge в этом конкретном источнике оставляет `FINAL_ONLY` даже после расширения механических данных.

Даже при добавлении одного полного `matchup` его вес 0.30 ниже минимума 0.55 и даёт лишь одну ось. Будущая численная оценка требует как минимум ещё одной **независимо подтверждённой** оси с достаточным суммарным весом; массового выставления score всем героям эти источники автоматически не гарантируют.
