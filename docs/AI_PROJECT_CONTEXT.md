# Dota Hub — текущий контекст после промпта №09

Дата: 23 октября 2026. Реализованы этап 1 и серверные модули этапа 2 (04–09). Текущий продукт — **ручной групповой `/match <id>` → OpenDota → анализ → краткий ответ бота → Telegram Mini App**. Автопоиска матчей, Steam-привязки, профилей, магазина, заданий и монеток в текущем объёме нет. История решений до №09 сохранена отдельно: [архив контекста](history/AI_PROJECT_CONTEXT_BEFORE_09.md), [план этапа 1](STAGE1_PLAN.md).

## Текущая архитектура

Модульный монолит Python 3.12+, FastAPI, aiogram 3.x, SQLAlchemy/asyncpg, PostgreSQL; React + TypeScript + Vite. Web и polling — два процесса одного backend. Redis, Celery, отдельные микросервисы и LLM не используются.

Бот принимает команды только в явно разрешённых группах. Быстро подтверждает запрос, затем `MatchAnalysisService` использует `MatchIngestionService`: PostgreSQL TTL-кэш либо OpenDota. Нормализатор №06 и анализаторы №07A/07/08 формируют пять независимых публичных отчётов. В существующей таблице `match_analyses` сохраняются пять записей разделов и одна запись состояния `group_flow_v1`. Схема БД остаётся `0001_initial`; новых миграций нет.

Обработка одного ID сериализуется внутри polling-процесса. Второй polling-процесс блокируется PostgreSQL advisory lock при запуске. Кэш отчётов проверяется по содержимому snapshot и версии конфигурации. При старте единственный worker отмечает незавершённые записи как failed/WORKER_RESTARTED; повторная команда безопасно возобновляет обработку. GET ничего не загружает и не пересчитывает. Ограничения: 10 запросов группы в минуту, cooldown пользователя в группе, предел активных задач.

Бот отправляет ограниченный по длине текст с `parse_mode=None`, счётом/победителем при наличии данных, оценками драфта либо «нет данных», индексами исполнения только выше low confidence и числом доступных событий. Кнопка — обычный URL `https://t.me/<bot_username>?startapp=match_<id>`; `web_app` в группе не используется.

## API и доступ

Все шесть read-only маршрутов требуют Bearer session после серверной проверки подписанного raw `initData`:

- `/api/v1/matches/{match_id}/overview`
- `/api/v1/matches/{match_id}/players`
- `/api/v1/matches/{match_id}/draft`
- `/api/v1/matches/{match_id}/ruiner`
- `/api/v1/matches/{match_id}/timeline?type=hero_kill&side=radiant`
- `/api/v1/matches/{match_id}/analysis/status`

Конверт `schema_version=1`: match_id, status, available_sections, data, error `{code,message,retryable}`, limitations, model_version, config_version, analyzed_at, completeness и retry_after_seconds. Ready-раздел — 200; queued/running — 202; статус существующей записи — 200 даже для failed. Неизвестный ID — 404, OpenDota недоступен — 503, лимит — 429, некорректный ответ — 502, неправильный ID — 422, нет сессии — 401. Health `/api/v1/health` и `/api/v1/health/db`, auth-контракты сохранены. Подробности — [передача frontend](STAGE3_FRONTEND_HANDOFF.md).

**MVP-доступ:** любой авторизованный пользователь Mini App может прочитать известный анализ по Match ID. Приватности по группе нет. `chat_instance`, URL и start-параметр не доказывают членство в группе. Чужой пользователь с валидной сессией может открыть пересланную ссылку; это ожидаемое поведение. Telegram-профиль из auth не включается в match DTO; account_id/steam_id/raw snapshot не выдаются через match API.

## Mini App и этап 3

Минимальный smoke уже читает raw initData и стартовый match ID, проходит auth, переходит на `/matches/:matchId`, запрашивает раздел и показывает loading/pending/error/готовность. Token хранится только в памяти React. Запросы отменяются при смене экрана; истечение сессии убирает доступ. Подробные экраны ещё не нарисованы.

Вкладки этапа 3: **Обзор, Драфт, Игроки, Ход матча, Индекс ошибок / Вывод**. Визуальное направление: существующие графитовые поверхности, тёмно-фиолетовый акцент, мобильная компоновка и safe areas. Точный макет и обязательные состояния: [STAGE3_FRONTEND_HANDOFF.md](STAGE3_FRONTEND_HANDOFF.md).

## Достоверность и ограничения

Источник игровых данных — OpenDota `/matches/{id}`. После Alpha-исправления №7A.1 групповой и локальный сценарии дополнительно запрашивают `/heroes/{hero_id}/matchups` для нового расчёта Draft Analyzer; статистика агрегатная, без подтверждённого патча, и не заполняет недостающие пары вымышленными значениями. Draft Analyzer поддерживает описательный каталог 127 героев и качественные механические профили 11 героев для patch=60; доказанного численного применения этих профилей к историческому patch=60 нет. Подтверждённая последовательная политика только game_mode=22/patch=46. Современные или неполные драфты обычно `FINAL_ONLY`, at_pick=null; отсутствующие оценки нельзя подменять 50 или 0. Для матча 9051271323 все численные оценки после исправления null; подробнее — [отчёт 07A.1](STAGE2_07A1_ALPHA_BUGFIX_REPORT.md). Индекс ошибок — относительная эвристика, не доказательство вины. Хронология содержит только исходные события и отдельно возможные переломы; partial/unavailable — нормальное состояние.

Фикстура `8888765469` в №09 синтетическая, этот ID не запрашивался у OpenDota. Ранее сохранённый реальный матч `9051271323` используется в тестах №07A/07/08. В №09 живая группа/HTTPS WebView не проверялись. Финальные результаты и решение GO/NO-GO — [STAGE2_09_QA_REPORT.md](STAGE2_09_QA_REPORT.md), эксплуатация — [GROUP_FLOW_OPERATIONS.md](GROUP_FLOW_OPERATIONS.md).
